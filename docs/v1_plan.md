# V1 implementation plan

> Agreed with the owner on 2026-11-09. Phase 1 (Next.js UI) is detailed; phases 2–5 are outlines to be planned when they start.

## Context
The MVP is complete. Its pipeline works end to end: scrapers → Postgres → FastAPI → Streamlit, with 4 providers including Event Chip Timing. The Streamlit UI (`src/chipt/ui/app.py`, 3 pages) was always meant to be thrown away (spec §5.9). V1 (spec §3) asks for:
1. a slick, user-centric UI in Next.js
2. a move to API feeds
3. more providers and races
4. more advanced analysis
5. better search

The owner wants to **start with the UI**. Decisions they've made:
- **Scope:** parity with Streamlit, plus a home dashboard and a result detail page. Streamlit is removed once parity is reached.
- **Look:** clean and minimal. Neutral shadcn/ui base, one sporty accent colour, light and dark mode, mobile-first.
- **Testing:** light automated checks (typecheck, lint, build, Playwright smoke tests), with the manual checklist kept.

## V1 roadmap (phase 1 detailed below; the rest are outlines to plan when they start)
| Phase | Goal | Notes |
|---|---|---|
| **1. Next.js UI** | Replace Streamlit | This plan |
| 2. API feeds | Prioritised list of results platforms with APIs; add an `api` ingest type; migrate the priority providers | Spec §5.5 already anticipates this |
| 3. More data | More providers and races per provider; Grafman-style multi-year sets | Each new provider still goes through the robots.txt/ToS check |
| 4. Advanced analysis | Position/percentile in field, age-group rank trends, all-groups overview; age-grading if age/DOB can be captured | Spec §5.4 open question on age buckets |
| 5. Better search | Results grouped per event, name variants, club/age hints taken from already-claimed results | Builds on `pg_trgm` |

## Phase 1: Next.js UI

### Stack (from CLAUDE.md)
- **Next.js 15 (App Router) + React 19 + TypeScript**, **Tailwind v4**, **shadcn/ui**, and **Recharts** through shadcn's chart components.
- **New dependencies, which need justifying against the stack:**
  - `@tanstack/react-query`: server-state cache. Claim and unclaim then refresh search, My Results and the analysis without manual plumbing.
  - `openapi-typescript` + `openapi-fetch`: generates TS types from FastAPI's `/openapi.json`, so the Pydantic models stay the single source of truth (CLAUDE.md: "keep the canonical schema in Pydantic").
  - `@playwright/test`: smoke tests. Playwright is already in the stack.
  - `next-themes`: dark mode. This is the shadcn convention.
- Use **Node 22 LTS** (add `.nvmrc`). The installed Node 21 is past end of life. Package manager: npm.

### Repo layout
```
web/                         # new Next.js app (monorepo, next to src/chipt)
  app/
    layout.tsx               # shell: top nav (Dashboard, Find, My results, Analysis), theme toggle
    page.tsx                 # Dashboard
    find/page.tsx            # Find & Claim
    results/page.tsx         # My results
    results/[id]/page.tsx    # Result detail
    analysis/page.tsx        # Analysis (?discipline=&distance=)
  components/ui/             # shadcn-generated
  components/                # ResultTable, ClaimBar, GroupPicker, TimeChart, StatCard, EmptyState…
  lib/api/schema.d.ts        # generated by `npm run gen:api` (committed)
  lib/api/client.ts          # openapi-fetch client + react-query hooks
  lib/format.ts              # HH:MM:SS, pace, signed deltas (port fmt_duration / fmt_signed from ui/app.py)
  e2e/                       # Playwright smoke tests
```
- Config: `NEXT_PUBLIC_API_BASE_URL` (default `http://127.0.0.1:8000`) in `web/.env.local`, documented in `.env.example`. `CORS_ALLOWED_ORIGINS` already includes `http://localhost:3000` (`src/chipt/config.py`).
- Pages are client components that fetch through react-query. The API stays the only backend: no Next server actions and no second DB access path.

### Pages
1. **Dashboard `/`**
   - Headline stats: results claimed, races, disciplines.
   - A **PB card per comparison group**: PB, latest vs PB, trend arrow, sparkline.
   - Recent results.
   - Empty state when nothing is claimed: "Find your results" → `/find`.
2. **Find & Claim `/find`**
   - Name search box plus filter chips (discipline, provider, race, age group) filled from `/filters`.
   - Filters are kept in the URL, so searches can be shared or refreshed.
   - Results are grouped by event, each with a match-confidence badge and a DNF badge where it applies.
   - Rows have checkboxes, and a sticky "Claim N selected" bar applies the change. One POST/DELETE per result, then the queries are invalidated.
   - Already-claimed rows are marked and can be unclaimed.
3. **My results `/results`**
   - Sortable table: date, race, discipline/distance, time, pace, positions.
   - Filter by discipline; unclaim.
   - Each row links to its detail page.
4. **Result detail `/results/[id]`**
   - Race header, time (labelled chip or gun), pace.
   - Positions overall, gender and category, shown as "N of M".
   - Provider and source link.
   - Splits are out of scope, so nothing from `raw` is shown.
5. **Analysis `/analysis`**
   - Group picker from `available_groups`, defaulting to the largest group (the API already does this).
   - Finish-time line chart with PB markers.
   - Pace chart for single-discipline groups only.
   - Stat cards: PB, latest vs PB, trend s/yr.
   - Table of points.
- Throughout: loading skeletons, an API-down error banner (same idea as `show_api_error` in `ui/app.py`), mobile layouts, and accessible chart colours (load the `dataviz` skill when building the charts).

### Small API additions (`src/chipt/api/main.py`, `src/chipt/db/repository.py`, `src/chipt/schemas.py`)
- **`time_source: "chip" | "gun"` on `ResultOut`**, taken from `raw->>'_time_source'` (default `chip`), so the UI can show "gun time" honestly (Event Chip Timing only has gun times). Add it to `_RESULT_COLUMNS`.
- **`event_finishers: int` on `ResultDetailOut`**: count of `finisher` results in the event, for "N of M".
- **`GET /me/summary`**: one call for the dashboard. Totals, plus, for each comparison group, the output of `analyse_group` (`src/chipt/analysis/timeseries.py`) without points (PB, most recent, delta, trend, count) and the latest few results. It reuses `comparison_groups` / `claimed_group_rows` (`repository.py`).
- No other contract changes. Existing endpoints stay compatible while Streamlit still runs.

### Constraints carried over
- The UI only shows data; it sends nothing to an LLM, so displaying data from AI-opted-out providers (RunThrough, Event Chip Timing) is fine.
- No secrets in `web/`; the only frontend variable is the public API URL.
- Local-only deployment. Hosting is still deferred (spec §6).
